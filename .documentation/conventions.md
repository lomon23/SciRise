# Базові правила для написання коду:

## Про Проект:
 Наш проект SciRise це певний мультитул для виклдадачів, та репетиторів якім набридло переключатьись між вікнами під час викладання, тому ми розробляємо проект в якому буде зкомбіновано звінки, канали, дашборди, ствоерння, та заготування курсів. Наша основна задача розробити оптимізований, та зручний сокет сервер, для роботи з відо та голосовими звінками, та дашборду, також реалізувати зручний та оптимізований desktop додаток, для того щоб навіть викладачі з слабикими компютерами могли без проблем корисутватись нашим додатком  

## Architecture Overview
 Backend: Django (REST API).
 Frontend: React.
 Desktop: C++ / Qt.
 Database: PostgreSQL.
 Взаємодія: Frontend та Desktop спілкуються з Backend виключно через JSON API

##  Нейменування:
 Змінні пишемо через snake_case.
 Класи пишемо PascalCase
 методи пишемо через back(snake_case) front(CamelCase)

## GIT
 мова комітів тільки англійська
 Кожен коміт повинен починатися з feat('вписуємо з відки коміт web/back/desktop'): fix(): docs(): refactor():
 гілки повинні називатись feat/'назва гілки', refactor/'назва гілки', fix/'назва гілки' 
 Код нівякому разі не можна нікуди мержити, лише відправляти запити на CI CD після перевірки, можна відправляти на підтвердження мерджу 
 заборона force push  у спільну гілку категорично заборонено, зразу смертний приговор 
 в канбан дошці у вас є таска, на основі неї будуються issue, при кожному коміті треба прикріпляти те що ви якраз робити це робиться за допомогою комітів коміт повинен так виглядати "feat(desktop)created QML form (ref #1)" ось це номерування пиеш при кожнмуо issue  так що дивіться щоб в інший issue  не закинути. якщо коміт закриває цю таску то пишемо не (ref #1)  а  (closes #1)
